# 测试与已知限制

## 离线检查

运行 `zsh test.sh`，当前共 44 项。覆盖内容包括：

- 可信主机、路径、端口及当前用户 IP 的校验。
- HTTP / JavaScript 重定向解析，以及入口超时后的备用入口。
- 取消任务、双重参数编码和 RSA 数学参考。
- 已登记 Wi-Fi、外接显示器、暗唤醒与系统睡眠。
- 旧版状态文件兼容性、认证失败分类及服务器数据回显不入日志。

测试仅使用合成数据；`RSAFixture.json` 的示例密码和公钥不是校园网真实凭据。

## 已完成的本机验证

环境：Apple 芯片、macOS 27.0.1、Wi-Fi、校园网 default 服务、Clash Verge 2.5.8。

| 场景 | 结果 |
| --- | --- |
| 真实退出认证后自动登录，1.0.5 | 成功获取新引导、提交认证并确认直连联网，本次检查约 6.72 秒 |
| 保持 Clash 系统代理开启 | 认证测试前后代理配置一致 |
| 接电源、合盖、外接显示器，苹果菜单睡眠后唤醒，1.0.3 | 唤醒约 5 秒后完成检查，触发原因为系统唤醒 |
| 连续启用三次，1.0.5 | 均成功，监听器进程保持运行 |
| 关闭设置窗口 | 后台继续运行，无 Dock 常驻图标 |

1.0.3 空闲抽样的 RSS 约 15 MB，30 秒内累计 CPU 时间未增加。这是单机短时测量，尚未进行完整电池功耗测试。

## 已知限制

- 自然唤醒曾在旧版触发一次认证拒绝，旧日志不足以确定具体原因。1.0.5 的受控认证测试通过，仍需继续观察自然唤醒。
- 原认证仍有效的唤醒检查，与认证已失效时的重新登录，是不同验证场景；不能把其中一个当作另一个的完整测试。
- 当前只登记并处理一个 Wi-Fi 配置。切换校园内不同网络配置时，可能需要重新保存。
- 只实现校园网 default 服务，其他运营商未适配；验证码、SSO 或新增认证步骤需要网页处理。
- 学校修改认证地址、页面特征或加密协议后，需要重新适配。
- 声明的部署目标是 macOS 14+，尚未在旧版 macOS 或 Intel Mac 上实测。
- 应用尚未做 Developer ID 签名和 Apple 公证。
- 物理开盖、漫游、多设备限制及长时间睡眠后的各种组合尚未完成系统性测试。

原始联网报告只保存在本地忽略的 `build/` 目录。公开仓库保留验证摘要，不附个人配置、会话参数或账户信息。
