# 测试与已知限制

## 离线检查

- `zsh test.sh` 运行常规版的 44 项检查。
- `zsh test-tun.sh` 在 TUN 构建下运行同样的 44 项检查，再运行 20 项 TUN 专项检查，覆盖物理 Wi-Fi 选择、Fake-IP 过滤和 HTTPS DNS 回包校验。

两版共有检查覆盖：

- 可信主机、路径、端口及当前用户 IP 的校验。
- HTTP / JavaScript 重定向解析，以及入口超时后的备用入口。
- 取消任务、双重参数编码和 RSA 数学参考。
- 已登记 Wi-Fi、外接显示器、暗唤醒与系统睡眠。
- 旧版状态文件兼容性、认证失败分类及服务器数据回显不入日志。

测试仅使用合成数据；`RSAFixture.json` 的示例密码和公钥不是校园网真实凭据。

## 已完成的本机验证

在 Apple 芯片 Mac 上使用校园 Wi-Fi 的 default 服务。TUN 版验证于 2026-11-19，环境为 macOS 27.2、Clash Verge 2.5.10，开启 TUN 和 Fake-IP，关闭系统 HTTP 代理。常规版的早期测试使用 macOS 27.0.1 和 Clash Verge 2.5.8。

| 场景 | 结果 |
| --- | --- |
| TUN 开启，退出认证后触发后台检查，1.0.6 | 确认学校重新要求认证，后台登录成功并通过直连 HTTPS 检测。从退出到完成验证约 10 秒 |
| TUN 开启，关开 Wi-Fi 后连回校园网，1.0.6 | 后台自动记录「Wi-Fi 连接变化」，检测结果为「已联网，无需重复登录」。当时校园网认证仍有效 |
| 真实退出认证后自动登录，1.0.5 | 成功获取新引导、提交认证并确认直连联网，本次检查约 6.72 秒 |
| 日常唤醒，1.0.5 | 10 月 28 日有一次系统唤醒后自动登录成功，约 10 秒确认联网 |
| 保持 Clash 系统代理开启 | 认证测试前后代理配置一致 |
| 接电源、合盖、外接显示器，苹果菜单睡眠后唤醒，1.0.3 | 唤醒约 5 秒后完成检查，触发原因为系统唤醒 |
| 连续启用三次，1.0.5 | 均成功，监听器进程保持运行 |
| 关闭设置窗口 | 后台继续运行，无 Dock 常驻图标 |

1.0.3 空闲抽样的 RSS 约 15 MB，30 秒内累计 CPU 时间未增加。这是单机短时测量，尚未进行完整电池功耗测试。

## 已知限制

- 1.0.6 已分别验证 TUN 下的登录流程和重连触发。TUN 保持开启、认证失效后由自然唤醒直接触发完整登录的组合仍待实测。
- 目前已验证上述 Clash Verge 配置。其他 TUN 协议栈、严格路由和其他 VPN 的组合仍待测试。
- 当前只登记并处理一个 Wi-Fi 配置。切换校园内不同网络配置时，可能需要重新保存。
- 只实现校园网 default 服务，其他运营商未适配；验证码、SSO 或新增认证步骤需要网页处理。
- 学校修改认证地址、页面特征或加密协议后，需要重新适配。
- 声明的部署目标是 macOS 14+，尚未在旧版 macOS 或 Intel Mac 上实测。
- 应用尚未做 Developer ID 签名和 Apple 公证。
- 物理开盖、漫游、多设备限制及长时间睡眠后的各种组合尚未完成系统性测试。

公开仓库仅收录验证摘要。原始联网报告和运行日志保留在本机。
